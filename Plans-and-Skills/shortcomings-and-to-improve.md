# Looking at shortcomings in this experiment. 


## Data quality is not as high as it could be. 


At the moment the data is created by pulling public modules and looking at the terraform registry. It is a best efforts approach however there has not been a strong plan in advance on how to get this data and validate how valuable it is. 


As a prototype this is acceptable but as a long term project we would want to make a plan on how best to get this information and confirm it is accurate. 


## There hasn't been a plan on the tools languages and processes chosen to progress the test. 


The current project has been given a plan but there is not guidance given as to the tool to use to complete the work. 

To address this if there were to be a "2.0" of this I would like to do the research or take guidance on specifying which languages and tools would be best to be used. 


I feel the lack of specificity make it more likely that there can be halluncinations and that we can lose conttrol and understanding of the final product. 


## There hasn't be a focus on security. 


Security hasn't been mentioned once in the plan and in any of the steps since. 


Security should be a focus on all steps of this process - ideally I would need to have a greater understanding of potential vulnerabilities and make security a priority in any skills and any plans going forward.
